# Step 3: Covers

## Context

Steps 1–2 (`9e72d6e`, `564b4b0`) built storage and the scanner; every book
now has a row with title/authors/language/ISBN, but `cover_path` is always
empty — `CreateBook` already accepts it (it's in the
INSERT column list), nothing has ever populated it. DESIGN.md's Covers
section is explicit about the shape: extract from the EPUB, resize to ~400px
on the long edge, JPEG, written to a derived directory keyed by content
hash, with only the path stored in the DB row.

This is the last piece of the "see what books I have" story that doesn't
need the web UI to exist first — once this lands, a book row is
feature-complete on its own (text metadata + cover), and the only things
left before a UI can show something worth looking at are the UI itself.

**Scope boundary**, same shape as step 2's: cover extraction happens only
when a book is newly created during a scan (mirrors how embedded text
metadata is only parsed on creation). EPUB only — FB2 cover extraction
stays deferred alongside FB2 text metadata. No regenerate-on-demand
endpoint; DESIGN.md's "regenerable from the source file" is what makes the
derived directory disposable, not a feature this step has to build.

## Flagged gap (pre-existing, not fixed by this step)

The already-shipped scanner (step 2) can't correctly represent DESIGN.md's
"one entry with multiple file locations" v1 duplicate-detection behavior —
see `docs/plans/2026083002-book-file-locations.md` for the bug and its fix.
Not touched here — covers doesn't depend on it, though implementing that
step first means covers builds on the corrected scanner shape rather than
the current one.

## `internal/epub` changes

Extend `opfPackage` to also parse the `<manifest>` block and the
`<metadata><meta name="cover" content="...">` element, and add a
`Cover []byte` field to `Metadata`.

**Cover lookup**, checked in this order (covers both EPUB versions in the
wild):
1. EPUB3: a `<manifest><item properties="cover-image" href="...">` — the
   `properties` attribute is a space-separated token list, so match on
   membership, not exact string equality.
2. EPUB2: `<meta name="cover" content="ITEM-ID">` in `<metadata>`, then the
   manifest item whose `id` equals that content value.
3. Neither found → `Cover` stays `nil`. Not an error — most of
   `ReadMetadata`'s other fields are still valid without a cover, same as a
   book with no ISBN.

The matched item's `href` is relative to the **OPF file's own directory**
inside the zip, not the zip root (e.g. OPF at `OEBPS/content.opf`, href
`images/cover.jpg` → zip entry `OEBPS/images/cover.jpg`). Resolve with the
`path` package (zip entries are always `/`-separated, regardless of host
OS) — `path.Join(path.Dir(opfPath), href)`.

If the resolved entry can't be opened (malformed epub, dangling reference),
leave `Cover` nil rather than failing `ReadMetadata` — same non-blocking
treatment as everything else here.

## `internal/cover` (new package)

**`cover.go`**
- `Store(dir, contentHash string, raw []byte) (path string, err error)`.
- Decodes `raw` via `image.Decode` (blank-import `image/jpeg`, `image/png`,
  `image/gif` for format registration — covers a real epub cover, not
  necessarily every possible image type, which is fine: an undecodable
  cover is exactly the "corrupt cover" case DESIGN.md already says is
  fine to skip).
- Resizes so the **long edge is ~400px, never upscaling** a smaller source
  (DESIGN.md says "resized to ~400px," and scaling a small placeholder
  image up to 400px would add file size without adding real resolution —
  the scale factor is `min(1.0, 400/longestEdge)`). Uses
  `golang.org/x/image/draw` (`draw.CatmullRom.Scale`) — an official Go
  sub-repo, pure Go like everything else here, rather than hand-rolling
  interpolation.
- Encodes as JPEG (`image/jpeg`, quality 85 — the DESIGN.md-cited 30–60KB
  range is a rough target, not something this step asserts exactly in
  tests, since it depends on source image complexity).
- Writes to `filepath.Join(dir, contentHash+".jpg")`; `dir` is created by
  the caller (same MkdirAll-at-startup pattern `main.go` already uses for
  `DB_PATH`'s and `LIBRARY_DIR`'s directories), not by `Store` itself.
- Returns the written path, or an error for genuinely bad input (decode
  failure) — the caller (scanner) treats that as "no cover," logs, and
  keeps the book row.

**`cover_test.go`** — build a solid-color image in memory (`image.NewRGBA`
+ manual fill, no need for a real photo) at a couple of sizes:
- 800×600 in → 400×300 out (long edge scaled to 400, aspect preserved).
- 100×80 in → unchanged 100×80 out (no upscaling).
- Corrupt/non-image bytes → `Store` returns an error, no file written.

## Scanner wiring (`internal/scanner`)

- `Scan`'s signature grows a `coversDir string` parameter — it's still
  early/unstable (only called from `main.go` and its own tests), so this is
  a straight signature change, not a compatibility shim.
- In the "genuinely new content" branch (the only place metadata is already
  parsed), after `epub.ReadMetadata`: if `meta.Cover` is non-empty, call
  `cover.Store(coversDir, hash, meta.Cover)`. On success, set
  `book.CoverPath` before `CreateBook`. On error, log and leave
  `CoverPath` empty — exactly the same "don't let one bad file block the
  rest of the sweep" treatment already used for per-file scan errors.
- No change to the "moved" or "unchanged" paths — content hash is the
  cover's key, so a moved/renamed file's cover is already sitting at the
  right path under `coversDir` and `cover_path` in the DB doesn't need to
  change.

**`scanner_test.go`** — extend the existing EPUB test-fixture builder to
optionally embed a manifest + a small in-memory image as the declared
cover; add a `coversDir` temp dir to the existing scan tests and assert:
a book created from a fixture with a cover has a non-empty `CoverPath`
pointing at a file that exists and decodes as a JPEG; a fixture without a
cover still creates its book row successfully with `CoverPath` empty.

## Wiring (`cmd/server/main.go`)

- New env var `COVERS_DIR` (default `./data/covers`), `MkdirAll`'d at
  startup next to the existing `LIBRARY_DIR` handling.
- Thread `coversDir` through `runScan`/`periodicScan` into `scanner.Scan`.

## Dependency

`go get golang.org/x/image` (for `golang.org/x/image/draw`) — the standard,
minimal choice for image scaling in Go: an official golang.org sub-repo,
pure Go, no cgo, same profile as `modernc.org/sqlite`.
