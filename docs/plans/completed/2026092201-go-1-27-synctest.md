# Go 1.27, `testing/synctest` and `httptest.NewTestServer`

## Context

`go.mod` says `go 1.26.1` and the Dockerfile builds on `golang:1.26`, while the
installed toolchain is go1.27.1. Several tests wait on real time: `time.Sleep`,
`time.After` limits, and handlers that sleep 50 ms against a 5 ms deadline. That
costs about 12 s per run (retry backoff alone is 5.5 s, the watcher about 5 s,
the slow upload 1.4 s). It also makes those tests timing-shaped, which is what
backlog `2026090701-enrich-tests-have-wall-clock-deadlines.md` records.

Go 1.25+ `synctest` runs a test on a fake clock that advances only when every
goroutine in the bubble is durably blocked. Go 1.27 adds two things:

- `synctest.Sleep`, which is `time.Sleep` followed by `synctest.Wait`.
- `httptest.NewTestServer(t, h)`. It uses an in-memory network, and
  `Server.Client()` routes *every* host, http or https, to that one server. It
  cleans up after itself, fails the test on a handler panic, and works inside a
  bubble.

The goal is to move every timing-dependent test that can run in a bubble onto
the fake clock, and to say why each remaining one cannot.

Decisions:
- Add an event-source seam to `scanner.Watcher` so its debounce tests run on
  fake time.
- Make `enrich.WithRateLimit` goroutine-free.
- Keep `sender.Worker.sendTimeout` as it is.

## Step 2: goroutine-free rate limiter (`internal/enrich/decorator.go`)

Today `newRateLimiter` starts a ticker goroutine that nothing stops. Inside a
bubble it never exits, so `synctest.Test` fails. In production, `run()` leaks
one such goroutine per provider.

Replace it with this:

- `rateLimiter{every, mu sync.Mutex, next time.Time}`.
- `wait(ctx)` reserves a slot under `mu`:
  - `slot = max(now, next)`, then `next = slot + every`.
  - If `slot` is in the future, wait on `time.NewTimer(slot - now)` or
    `ctx.Done()`.
  - When cancelled, give the slot back (`next = slot`) if nothing has reserved
    behind it, and return `ctx.Err()`. Callers rely on
    `errors.Is(err, context.DeadlineExceeded)` and on the worker's
    `ctx.Err()` checks.
- Don't use `golang.org/x/time/rate`. Its `Wait` fails early with a
  non-context error when the wait would pass the deadline, and the enrichment
  invariants rely on cancellation surfacing as `ctx.Err()`.
- Keep the `every <= 0` fallback to `DefaultRateLimitInterval`.
- Rewrite the type's doc comment. There is no ticker any more, and "at most one
  every `every`" becomes strictly true: a ticker with a fixed phase could admit
  two calls closer together than `every`.

## Step 3: watcher event-source seam (`internal/scanner/watcher.go`)

- Add `watchSet interface { Add(string) error; Remove(string) error;
  WatchList() []string; Close() error }`. `*fsnotify.Watcher` already
  satisfies it.
- Change `Watcher.fsw` to that type, and add fields
  `events <-chan fsnotify.Event` and `errors <-chan error`. `Run` and `probe`
  read these fields instead of `w.fsw.Events` / `w.fsw.Errors`.
- Split `NewWatcher` into two parts:
  - `NewWatcher` creates the fsnotify handle and passes it to an unexported
    `newWatcher(set, events, errs, libraryDir, settle, trigger)`.
  - `newWatcher` does the root `Add`, `logMount` and `Refresh`.
  - `NewWatcher` closes the handle if `newWatcher` fails.
- Leave `Refresh`'s `(dev, ino)` plus `WatchList()` logic, the probe, and the
  `maxDelay`/`recheck` fields unchanged.

## Step 4: pure-Go timing tests move to `synctest.Test`

Rules for every bubble:

- **Build everything inside the bubble with the bubble's `t`.** That covers
  `openTestDB`, workers, handlers and servers. `database/sql` starts a
  `connectionOpener` per pool, and `db.Close` (in `t.Cleanup`, which runs
  inside the bubble) must stop it there.
- **Replace the waits.** A "wait for state" loop becomes `synctest.Wait()`
  plus one check. A `time.After` failure limit becomes a plain receive, since
  a deadlock inside a bubble fails the test immediately.
- **Order around cancellation.** Cancel right after an `entered` signal. If the
  test goroutine blocks in between, the clock jumps to the production deadline
  (for example the sender's 5-minute limit).

Sites:

- **`internal/enrich/decorator_test.go`**
  - The three `WithRetry` tests: assert exact elapsed time (0.5 s + 1 s).
  - Add one case that pins the doubling and the `retryMaxDelay` cap. It is
    free now.
  - `TestWithRetryStopsOnCancellation` (the sleep at :271).
  - The three rate-limit tests: `PacesCalls` asserts elapsed == `every`
    exactly, and `ReturnsPromptlyOnCancellation` asserts exactly 20 ms.
- **`internal/providers/registry_test.go`**:
  `TestComposeRetriesAndNeverCachesAnError` (2 s) and the compose test above
  it.
- **`internal/storage/db_test.go:237`**
  (`TestConcurrentWritesFromDifferentGoroutinesBothSucceed`): replace the
  50 ms "still blocked" timer with `synctest.Wait()` and a non-blocking check
  of `secondDone`.
- **`internal/enrich/worker_test.go`**
  - `TestWorkerNotifyWakesIdleWorker`: `Wait` after starting `Run`, enqueue,
    `Notify`, `Wait`, then assert. The clock does not move, so the 1-minute
    tick cannot be what did the work, which closes the race that exists
    today.
  - `…CancellationLeavesJobRunningForRecovery` and
    `…CancellationIsNotRecordedAsAVerdict`.
- **`internal/sender/sender_test.go`**: `TestWorkerNotifyWakesIdleWorker`,
  `…CancellationLeavesRowSendingForRecovery`, and
  `TestWorkerTimeoutIsRecordedAsUnknownOutcome`. The last keeps its
  `sendTimeout` override and becomes exact.
- **`internal/scanner/watcher_test.go`**: `TestWatcherPokeNeverBlocks`.

## Step 5: HTTP tests move to `NewTestServer`

The in-memory network is easy to wire wrongly. These rules apply to every
conversion:

1. **Call `server.Client()` before anything reads `server.URL`, or don't read
   it at all.** `URL` is `""` until `Client()` starts the fake network, and
   Go leaves the evaluation order within a struct literal unspecified.
2. **Use fixed base URLs on reserved `.test` hosts** (`https://openlibrary.test`,
   `https://covers.openlibrary.test`, `https://www.googleapis.test`,
   `https://api.resend.test`, `http://covers.test`). A client wired wrongly then
   fails on DNS instead of reaching the real `example.com` or a real API.
3. **Use one server per client, and have the handler dispatch on `r.Host`.**
   A second server is unreachable, because the client sends every host to the
   server it came from. Count hits per host. Each package's test helper keeps
   its current shape, and the cover host's 404 moves to a `Host` branch.
4. **Take the transport from the test server.** Where a production
   constructor exists (`openlibrary.New`, `googlebooks.New`,
   `resend.NewClient`), build with it and set
   `httpClient.Transport = server.Client().Transport`. The tests then run the
   real `Timeout` and `CheckRedirect` rather than a copy set by hand. Use the
   same `Transport` object, not a clone: `Server.Close` shuts only its own
   transport's idle connections, and a clone's connections would leak
   goroutines out of the bubble.
5. **Wrap only the timing tests in `synctest.Test`.** The rest run fine
   without a bubble.

Per package:

- **`internal/openlibrary`**
  - Convert `testClient` and the four servers.
  - The 50 ms / 5 ms test (:233) runs in a bubble.
  - `TestByISBNRefusesARedirectOffHost` redirects `openlibrary.test` to
    `foreign.test` and asserts the foreign host saw 0 requests.
- **`internal/googlebooks`**
  - Convert `testClient`, `detailClient` and the inline clients at about
    1339, 1377, 1414 and 1502.
  - The timeout tests at :358 and :496 (the second keeps its key-redaction
    assertion) run in a bubble.
  - Rewrite `TestARedirectOffTheAPIHostNeverCarriesTheKey` as one server over
    `https://`. It needs both a foreign-name case and a same-name,
    different-port case, because the loopback version covered the port case.
- **`internal/resend`**: convert `testClient`, and put
  `TestSendExpiredContextIsDeadlineExceeded` in a bubble.
- **`internal/enrich/cover_test.go`**
  - Add one helper that returns `server.Client()` with
    `CheckRedirect = CheckCoverRedirect`. The tests at 138 and 154 currently
    use the default transport and would silently stop testing anything.
  - The 50 ms / 5 ms test (:101) runs in a bubble.
- **`internal/enrich/worker_test.go` `TestWorkerCoverOnlyCancellationLeavesJobRunning`**
  - Add `useCoverTransport(w, rt)` to `export_test.go`, next to
    `allowAnyCoverAddress`. It is test-only, so production still has no
    switch.
  - Run the test in a bubble against a `NewTestServer` at `http://covers.test`.
- **`internal/web/import_test.go` `TestASlowUploadStillDeliversItsAnswerUnderAWriteTimeout`**
  - Set `Config.WriteTimeout` before `Client()`, and post to a fixed URL.
  - Run it in a bubble. In-memory connections implement deadlines through
    `time.AfterFunc`, so the fake clock drives both `WriteTimeout` and
    `extendDeadlines`. The 1.3 s of `slowBody` sleeps become free.
  - If the mutation check below cannot make it fail, keep it on loopback.

Every test that deliberately stays on loopback switches to
`httptest.NewTestServer(t, h)` plus `Start()` or `StartTLS()`. That gives
automatic cleanup and handler-panic reporting, and drops `defer
server.Close()`. The sites are:

- the worker cover tests: the `coverServer` helper and the two
  loopback-refusal tests at 1152 and 1185;
- import `TestAnOverCapUploadStillReadsItsRefusalBack`;
- import `TestADisabledImportStillReadsItsRefusalBack`.

## Step 6: watcher debounce tests on a fake source

In `watcher_test.go`, add:

- `fakeWatchSet`: a mutex-guarded set of paths with `Close`.
- `events` and `errors` channels created inside the bubble.
- `completeProbe(t, dir, events)`: calls `synctest.Wait()` (the probe is then
  parked in its select), finds `.watch-probe-*` in `dir`, and sends its
  `Create`.

Convert these tests:

- **`TestWatcherPokesOnceForABurst`**: send 20 `Create` + `Write` events.
  - After `synctest.Sleep(settle - 1ns)` there is no poke.
  - After `synctest.Sleep(1ns)` there is exactly one.
  - After `synctest.Sleep(3 * settle)` there is none. The drain goroutine and
    the counter go away.
- **`TestWatcherPokesWhileEventsKeepArriving`**: send one event every
  `synctest.Sleep(10ms)`. There is no poke before `maxDelay`, and one on the
  first event at or after it.
- **`TestWatcherIgnoresPartialDownloadsUntilRenamed`**: `.part` events give no
  poke over 4 × settle. The `Rename` + `Create` pair gives a poke at settle.
- **`TestWatcherProbeDoesNotPoke`**: complete the probe, then also send the
  probe file's `Remove` so `Run`'s loop filters it. That is the case
  `probeName` guards. Assert no poke and that the file is gone.
- **`TestWatcherProbeDoesNotDisturbAnExistingPath`**: complete the probe, with
  no timing guess.

New tests this makes cheap:

- A qualifying event that the probe swallowed still arms the debounce. This is
  the `pending` path, which is untested today.
- A probe with no event times out after `watchProbeTimeout` (2 s of fake
  time). It warns and `Run` carries on.

## What stays on real time, and why

Put this in the new testing note:

- **The watcher tests that touch the kernel:** `PokesOnRemoval`, the
  `Refresh*` tests, `RecoversAfterTheLibraryDirectoryIsReplaced`, and
  `ReleasesTheKernelWatches`. What they test is kqueue/inotify behaviour. A
  real fsnotify reader sits in a syscall, which is never durably blocked, so a
  bubble can never go idle.
- **`internal/storage/db_test.go:129`:** SQLite's busy handler sleeps through
  a real `nanosleep` on Linux (Go `time.Sleep` on darwin). In a bubble it
  would pass on a Mac and fail in CI.
- **`internal/scanner/scanner_test.go:1956`:** the 1 ms sleep is a poll
  interval racing `Scan`'s real I/O. In a bubble the poller could only wake
  after `Scan` finished, so the test would fail.
- **`cmd/server`:** real TCP `ListenAndServe`, `http.DefaultTransport`
  pooling and fsnotify. Its 5 s `time.After` limits fire only on failure.

## Corrections found while implementing

**Step 3's field names.** The event channels are `events` and `errs`, not
`events` and `errors`. A field named `errors` compiles, but `w.errors`
beside the `errors` package reads as the package.

**Verification step 4's last mutation.** It says a cover test should fail
on the scheme check once `CheckRedirect` is gone. The mutation that was
run removed `CheckRedirect = CheckCoverRedirect` from the in-memory
helper:

- `TestFetchCoverStopsAfterTooManyRedirects` fails, at 10 hops against a
  limit of 6.
- `TestFetchCoverRefusesARedirectToANonHTTPScheme` still passes, because
  net/http refuses to follow an `ftp://` Location on its own. That test
  cannot tell whether the policy is present. It could before this change
  too, and it is left as it was.
